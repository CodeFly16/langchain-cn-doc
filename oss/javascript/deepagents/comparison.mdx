本页面介绍 [LangChain 深度智能体](/oss/javascript/deepagents/overview)与 [Claude Agent SDK](https://platform.anthropic.com/docs/en/agent-sdk/overview) 的比较。两者都是用于构建自定义智能体的框架，但在执行环境、部署和供应商绑定方面做出了不同的权衡。

<Info>
    深度智能体已在 [OpenSWE](https://github.com/langchain-ai/open-swe) 和 [LangSmith Fleet](/langsmith/fleet/index) 的生产环境中使用。
</Info>

## 概览

| | **深度智能体** | **Claude Agent SDK** |
| --- | --- | --- |
| **智能体运行位置** | 沙箱内部，或沙箱外部远程执行命令 | 沙箱内部 |
| **执行后端** | 可插拔：[本地、虚拟文件系统、远程沙箱或自定义](/oss/javascript/deepagents/backends) | 其运行所在沙箱的本地文件系统 |
| **模型提供商** | 任何（Anthropic、OpenAI、Google 及 100+ 其他） | Claude（Anthropic、Bedrock、Vertex、Azure） |
| **按提供商/模型调优** | [框架配置](/oss/javascript/deepagents/profiles)（beta）：声明式的系统提示、工具、中间件和子智能体调整包，按提供商或特定模型注册 | 在每个模型调用点通过代码配置 |
| **部署** | 通过 [`deepagents deploy`](/oss/javascript/deepagents/deploy) 部署到 [LangSmith 托管云](/oss/javascript/langgraph/deploy)，或通过 [`langgraph build`](/langsmith/cli#build) 自托管[独立镜像](/langsmith/deploy-standalone-server) | [自托管](https://code.claude.com/docs/en/agent-sdk/hosting)。你需要自己构建服务器、认证和流式输出层。[Claude 托管智能体](https://platform.claude.com/docs/en/managed-agents/overview)是一个单独的产品 |
| **多租户** | [内置](/oss/javascript/deepagents/going-to-production#multi-tenancy)：作用域线程、每用户沙箱、RBAC | 自行构建 |
| **许可证** | MIT | MIT（Claude Code 本身是专有的） |

## 主要区别

### 智能体和执行环境

[将智能体连接到沙箱有两种模式](https://www.langchain.com/blog/the-two-patterns-by-which-agents-connect-sandboxes)：将智能体运行在沙箱*内部*，或将智能体运行在外部并**使用沙箱作为工具**。

Claude Agent SDK 仅支持第一种。你的智能体运行在沙箱内部，并针对沙箱的本地文件系统执行工具。Anthropic 的托管模型 [Claude 托管智能体](https://platform.claude.com/docs/en/managed-agents/overview)使用解耦模型，这反映了生产智能体架构的发展方向。

深度智能体两种都支持，并允许你选择[后端](/oss/javascript/deepagents/backends#quickstart)来将它们连接在一起。实际上，这意味着你可以：

- 在沙箱内运行智能体（与 Claude Agent SDK 相同的模式）。
- 在长期运行的容器中运行智能体，并[使用远程沙箱作为工具](https://www.langchain.com/blog/the-two-patterns-by-which-agents-connect-sandboxes)，通过网络执行命令。
- 为测试切换虚拟文件系统，或为你自己的基础设施切换自定义后端。

### 多租户

当你将应用程序产品化时，通常需要将其暴露给许多终端用户，并且必须为每个用户隔离环境。

在 Claude Agent SDK 中，SDK 将智能体绑定到其沙箱。要为每个用户提供隔离的执行环境，你必须构建一个 API 包装器，为每个用户启动一个沙箱，跟踪哪个沙箱属于谁，然后在之后关闭它。

深度智能体直接处理这些：在框架中[按用户或按助手](/oss/javascript/deepagents/going-to-production#lifecycle)配置沙箱，包含作用域线程、运行历史和 [RBAC](/oss/javascript/deepagents/going-to-production#team-access-control-rbac)。如果你使用 [LangSmith Sandbox](/langsmith/sandbox-auth-proxy)，你还可以开箱即用地获得认证代理，这样终端用户可以从沙箱调用第三方 API，而无需你为每个用户提供凭据。

### 生产智能体服务器

要将[自托管的 Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/hosting) 应用暴露给终端用户，你需要编写自己的 HTTP/WebSocket 或 SSE 服务器来调用智能体、流式传输 Token，并管理对话线程。该服务器由你构建、运维和保护。

深度智能体部署包含开箱即用的[智能体服务器](/langsmith/agent-server)：流式端点、线程管理、运行历史、webhook 和[认证](/langsmith/auth)。

### 托管云或自托管

Claude Agent SDK 部署是[自托管](https://code.claude.com/docs/en/agent-sdk/hosting)的。SDK 和 [Claude 托管智能体](https://platform.claude.com/docs/en/managed-agents/overview)是独立的产品。针对 SDK 编写的代码不能直接部署到托管产品。

深度智能体无需代码更改即可在两种模式下运行：

- **托管：**通过 [`deepagents deploy`](/oss/javascript/deepagents/deploy) 部署到 [LangSmith 托管云](/oss/javascript/langgraph/deploy)。
- **自托管：**运行 [`langgraph build`](/langsmith/cli#build) 生成可部署到任何地方的[独立 Docker 镜像](/langsmith/deploy-standalone-server)。

<Tip>
    如需支持任何模型提供商的托管智能体平台，请使用 [LangSmith Fleet](/langsmith/fleet/index)。[Claude 托管智能体](https://platform.claude.com/docs/en/managed-agents/overview)仅限于 Anthropic 生态系统。
</Tip>

### LLM

Claude Agent SDK 将模型、后端和部署打包在一起，并在三者之间优化支持。

使用深度智能体时，你可以独立选择模型提供商、执行后端和部署目标。通过选择此框架，你在模型和基础设施的选择上保留了最大的灵活性。

### 生态系统

Claude Agent SDK 是为 Claude 和 Anthropic 的产品体系量身打造的。深度智能体与更广泛的 LangChain 生态系统集成，包括用于可观测性、评估和部署的 LangSmith，并支持任何模型提供商。

## 总结

- **选择深度智能体**如果你想要模型和基础设施的灵活性、内置的多租户部署，以及无需代码更改即可选择托管或自托管。
- **选择 Claude Agent SDK**如果你已经投入了 Anthropic 生态系统，并希望自托管及自行构建 API、认证和多租户层。
