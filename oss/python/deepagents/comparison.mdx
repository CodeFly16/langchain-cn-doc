本页说明 [LangChain 深度智能体](/oss/python/deepagents/overview)与 [Claude Agent SDK](https://platform.anthropic.com/docs/en/agent-sdk/overview) 的对比。两者都是构建自定义智能体的 Harness，但在执行环境、部署和供应商耦合方面做出了不同的权衡。

<Info>
    深度智能体已在 [OpenSWE](https://github.com/langchain-ai/open-swe) 和 [LangSmith Fleet](/langsmith/fleet/index) 的生产环境中使用。
</Info>

## 概览

| | **深度智能体** | **Claude Agent SDK** |
| --- | --- | --- |
| **智能体运行位置** | 在沙箱内部，或在沙箱外部远程执行命令 | 在沙箱内部 |
| **执行后端** | 可插拔：[本地、虚拟文件系统、远程沙箱或自定义](/oss/python/deepagents/backends) | 运行所在沙箱的本地文件系统 |
| **模型提供商** | 任意（Anthropic、OpenAI、Google 等 100+ 家） | Claude（Anthropic、Bedrock、Vertex、Azure） |
| **按提供商/模型调优** | [Harness 配置](/oss/python/deepagents/profiles)（beta）：声明式的系统提示词、工具、中间件和子智能体调整包，按提供商或特定模型注册 | 在每个模型调用处的代码中配置 |
| **部署** | 通过 [`deepagents deploy`](/oss/python/deepagents/deploy) 部署到 [LangSmith 托管云](/oss/python/langgraph/deploy)，或通过 [`langgraph build`](/langsmith/cli#build) 自托管[独立镜像](/langsmith/deploy-standalone-server) | [自托管](https://code.claude.com/docs/en/agent-sdk/hosting)。你需要自行构建服务器、认证和流式传输层。[Claude 托管智能体](https://platform.claude.com/docs/en/managed-agents/overview)是一个独立产品 |
| **多租户** | [内置](/oss/python/deepagents/going-to-production#multi-tenancy)：作用域线程、按用户沙箱、RBAC | 自行构建 |
| **许可证** | MIT | MIT（Claude Code 本身是专有的） |

## 主要区别

### 智能体与执行环境

[将智能体连接到沙箱有两种模式](https://www.langchain.com/blog/the-two-patterns-by-which-agents-connect-sandboxes)：将智能体运行在沙箱*内部*，或将智能体运行在外部并**将沙箱作为工具使用**。

Claude Agent SDK 仅支持第一种。你的智能体在沙箱内运行，并针对沙箱的本地文件系统执行工具。Anthropic 的托管模型 [Claude 托管智能体](https://platform.claude.com/docs/en/managed-agents/overview)使用解耦模型，这反映了生产智能体架构的发展方向。

深度智能体同时支持两种模式，并允许你选择[后端](/oss/python/deepagents/backends#quickstart)来连接它们。在实践中，这意味着你可以：

- 在沙箱内运行智能体（与 Claude Agent SDK 相同的模型）。
- 在长期运行的容器中运行智能体，并[将远程沙箱作为工具使用](https://www.langchain.com/blog/the-two-patterns-by-which-agents-connect-sandboxes)，通过网络执行命令。
- 换入虚拟文件系统用于测试，或使用自定义后端适配你自己的基础设施。

### 多租户

当你将应用投入生产时，通常需要向许多终端用户公开，并且必须为每个用户隔离环境。

在 Claude Agent SDK 中，SDK 将智能体绑定到其沙箱。要为每个用户提供隔离的执行环境，你必须构建一个 API 包装器，为每个用户启动一个沙箱，跟踪哪个沙箱属于谁，然后事后清理。

深度智能体直接处理这些：在 Harness 中[按用户或按助手](/oss/python/deepagents/going-to-production#lifecycle)配置沙箱，包含作用域线程、运行历史和 [RBAC](/oss/python/deepagents/going-to-production#team-access-control-rbac)。如果你使用 [LangSmith Sandbox](/langsmith/sandbox-auth-proxy)，还可以开箱即用地获得认证代理，这样终端用户可以从沙箱调用第三方 API，而无需你为每个用户配置凭证。

### 生产级智能体服务器

要向终端用户公开[自托管的 Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/hosting) 应用，你需要编写自己的 HTTP/WebSocket 或 SSE 服务器来调用智能体、流式传输 Token，并管理对话线程。该服务器由你自行构建、运维和保障安全。

深度智能体部署开箱即用地包含[智能体服务器](/langsmith/agent-server)：流式端点、线程管理、运行历史、webhook 和[认证](/langsmith/auth)。

### 托管云或自托管

Claude Agent SDK 部署是[自托管](https://code.claude.com/docs/en/agent-sdk/hosting)的。SDK 和 [Claude 托管智能体](https://platform.claude.com/docs/en/managed-agents/overview)是独立的产品。基于 SDK 编写的代码不能直接部署到托管服务。

深度智能体无需代码更改即可在两种模式下运行：

- **托管模式：** 使用 [`deepagents deploy`](/oss/python/deepagents/deploy) 部署到 [LangSmith 托管云](/oss/python/langgraph/deploy)。
- **自托管模式：** 运行 [`langgraph build`](/langsmith/cli#build) 生成[独立 Docker 镜像](/langsmith/deploy-standalone-server)，可部署到任何位置。

<Tip>
    如需跨任何模型提供商的托管智能体平台，请使用 [LangSmith Fleet](/langsmith/fleet/index)。[Claude 托管智能体](https://platform.claude.com/docs/en/managed-agents/overview)仅限于 Anthropic 生态系统。
</Tip>

### 大语言模型(LLM)

Claude Agent SDK 的执行将模型、后端和部署捆绑在一起，并优化三者之间的支持。

使用深度智能体，你可以独立选择模型提供商、执行后端和部署目标。选择此 Harness 意味着你在模型和基础设施选择上保持最大的灵活性。

### 生态系统

Claude Agent SDK 专为 Claude 和 Anthropic 的产品体系量身打造。深度智能体与更广泛的 LangChain 生态系统集成，包括 LangSmith 用于可观测性、评估和部署，并支持任何模型提供商。

## 总结

- 如果你需要模型和基础设施的灵活性、内置的多租户部署，以及无需代码更改即可在托管或自托管模式间切换的选项，请**选择深度智能体**。
- 如果你已经深度投入 Anthropic 生态系统，并希望自行托管并构建 API、认证和多租户层，请**选择 Claude Agent SDK**。
